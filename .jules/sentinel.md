## 2026-10-03 - Non-ASCII Webhook Secret Headers Cause Unhandled Exception in HMAC Comparison
**Vulnerability:** In Python's `hmac.compare_digest(a, b)`, passing a string containing non-ASCII characters when `b` is ASCII raises `TypeError: comparing strings with non-ASCII characters is not supported`. If incoming webhooks accept string headers from external clients without regex validation before HMAC comparison, attackers sending non-ASCII secret token headers can cause 500 internal server errors or bypass custom exception handling.
**Learning:** `hmac.compare_digest` in Python enforces strict ASCII comparison when comparing standard `str` objects. Unsanitized external header strings passed directly into `hmac.compare_digest` can trigger uncaught type errors rather than clean boolean comparisons.
**Prevention:** Always validate format and character set constraints (e.g., using `_SECRET_RE.fullmatch()`) on untrusted secret input strings prior to `hmac.compare_digest()`, or convert strings to `bytes` if arbitrary encodings are supported.
